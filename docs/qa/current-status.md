# 현재 구현 상태 · 2026-10-14

## 1. 한 페이지 기록

기존 `basketball-matching` 저장소에 개선 화면과 공통 서버를 통합했다. 원래 카카오맵 시안 `index.html`과 `config.js`는 보존하며, 원래 Git 상태는 `backup/pre-improvement-20261014` 태그에 남아 있다. 작업 브랜치는 `codex/first-service`다. 최초 scaffold는 원본 HTML을 참고해 별도 구조로 만들었고, 현재는 사용자가 지정한 실제 저장소에서 이어서 작업한다.

| 구분 | 구현·검증한 내용 | 남은 연결 |
|---|---|---|
| 경기 찾기 | 출발지·이동 방식·일정·포지션 조건, 이동 시간 미확인 구분, 실제 지도·시설 핀 | 대중교통·자동차 실제 경로 REST 설정 |
| 시설·모집 | 공식 시설 2개, 주장 제안·미확인 표시, 승인된 팀의 모집·신청·수락 | 실제 모집팀 확보, 시설 추가·내용 확인 |
| 결제·환불 | 수락 후 기한, 서버 승인 접수, 테스트 주문·중복 방지·누적 환불·원장 | 토스 테스트 키 실물 검증, 이후 사업자·PG 계약·실결제 전환 |
| 변경 안내 | 원래 조건 보존, 계속 참여 확인, 변경 불참 전액 환불, 주최자 진행 기재 구분 | 현장 운영·분쟁 대응 기준 확인 |
| 알림 | 공통 알림함·읽음, 제한된 5분 반복, 현재 상태 재검사, 한 푸시 경로, 설정 필요 상태 | APNs HTTP/2 연결·Firebase·VAPID·알림톡 업체·실제 수신 |
| 설치 앱 | iOS/Android 프로젝트·native 자산 동기화, OS 보관소·앱 복귀·기기 등록·계정 정리 | Xcode·Android Studio/SDK/JDK·서명·양 OS 실제 빌드 및 기기 검증 |
| 운영 권한 | 팀 승인·시설 확인·모집 숨김/중단·신고·탈퇴·금융 미처리 확인 | 공개 운영 계정·정책·배포 준비 |

초기 플랫폼 수수료는 0%다. 참가비 자체는 팀의 비용이며, 현재 모든 결제는 실제 출금 없는 테스트다. 향후 플랫폼 수수료 5~10%는 참가자와 팀이 절반씩 부담하는 계산으로 분리했다. PG 비용 부담과 실제 계약 요율은 결정되지 않았다.

공개된 실제 모집이 없는 상태에서는 빈 모집 목록을 보여준다. 시설 등록과 대관·경기 확정은 서로 다르다. 저장된 이동 시간 조건을 실제 경로 확인 없이 맞는 경기로 판정하지 않는다. 카카오맵 연결과 카카오 로그인은 별도 설정이다.

로컬 미리보기는 `http://127.0.0.1:5173/#/matches`이며 웹·서버 개발 프로세스가 실행 중일 때 이용할 수 있다. 양 OS 앱을 완성했다고 판단하려면 위 표의 빌드·기기 검증까지 필요하다. 외부 공개·실제 돈 이동·스토어 제출은 진행하지 않았다.

## 2. 세 줄 요약

1. 기존 폴더와 카카오맵 설정을 보존하면서 개선 화면·공유 모집·테스트 결제·알림을 연결했다.
2. 웹·서버 자동 검증과 앱 자산 동기화를 확인했고, 실제 모집 없이 시설만 있는 상태를 정확히 표시한다.
3. 카카오 로그인·실제 경로·결제/푸시 제공자·양 OS 빌드 환경을 준비하면 외부 및 기기 검증을 이어갈 수 있다.
