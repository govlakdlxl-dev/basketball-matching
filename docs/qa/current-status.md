# 현재 구현 상태 · 2026-10-21

## 1. 한 페이지 기록

기존 `basketball-matching` 저장소에 개선 화면과 공통 서버를 통합했다. 원래 카카오맵 시안 `index.html`과 `config.js`는 보존하며, 원래 Git 상태는 `backup/pre-improvement-20261014` 태그에 남아 있다. 작업 브랜치는 `codex/first-service`다. 최초 scaffold는 원본 HTML을 참고해 별도 구조로 만들었고, 현재는 사용자가 지정한 실제 저장소에서 이어서 작업한다.

초기 플랫폼 수수료는 0%다. 참가비 자체는 팀의 비용이며, 현재 모든 결제는 실제 출금 없는 테스트다. 향후 플랫폼 수수료 5~10%는 참가자와 팀이 절반씩 부담하는 계산으로 분리했다. PG 비용 부담과 실제 계약 요율은 결정되지 않았다.

공개된 실제 모집이 없는 상태에서는 빈 모집 목록을 보여준다. 시설 등록과 대관·경기 확정은 서로 다르다. 저장된 이동 시간 조건을 실제 경로 확인 없이 맞는 경기로 판정하지 않는다. 카카오맵 연결과 카카오 로그인은 별도 설정이다.

로컬 미리보기는 `http://127.0.0.1:5173/#/matches`이며 웹·서버 개발 프로세스가 실행 중일 때 이용할 수 있다. 양 OS 앱을 완성했다고 판단하려면 위 표의 빌드·기기 검증까지 필요하다. 외부 공개·실제 돈 이동·스토어 제출은 진행하지 않았다.

## 2. 세 줄 요약

1. 기존 폴더와 카카오맵 설정을 보존하면서 개선 화면·공유 모집·테스트 결제·알림을 연결했다.
2. 웹·서버 자동 검증과 앱 자산 동기화를 확인했고, 실제 모집 없이 시설만 있는 상태를 정확히 표시한다.
3. Chrome 웹의 실제 카카오 로그인과 조건 복원을 확인했고, 경로·결제/푸시·양 OS 기기 검증이 남아 있다.

## 3. 검토와 실행 기록

2026-10-21 GitHub 업로드 전 검증은 Vitest 171/171, DB 권한 35/35, 브라우저 시나리오 10/10, 타입 검사와 웹·Worker 빌드를 통과했다. 첫 실행에서 알림 기기 선택 검증이 실패했으며, 이전 테스트의 기기 정보와 고정 시각이 섞이는 문제가 원인이었다. 해당 시나리오의 계정·토큰을 독립 fixture로 만들고 실패를 재현한 전체 파일 12개와 전체 검증을 다시 통과시켰다. 기존 카카오·서버 비공개 값이 개선 커밋 기록과 단일 HTML에 포함되지 않았는지 확인했다. 독립 시안은 `artifacts/농구매칭_단일시안.html`에 포함했고 README에 실행·내려받기 안내를 보완했다.

2026-10-18 카카오 키를 Git 제외 파일에 연결하고 데이터 삭제 옵션 없이 로컬 Supabase를 재시작했다. 제공자 설정 API의 카카오 활성화, 비공개 파일·실행 중 서버의 설정 일치, 재시작 전후 회원·신청·경기 수 보존을 확인했다. 웹 버튼에서 카카오계정 화면까지 이동했으며 실제 계정 로그인 완료를 뜻하지는 않는다. 타입 검사와 웹 빌드를 통과했다. 로그인 전 기기 조건을 새 계정으로 자동 이관하는 기능은 없으므로, 본인 로그인 후 계정에 조건을 저장하고 복원을 확인해야 한다.

이후 내장 브라우저의 계정 인증 경고와 Chrome의 `KOE205`를 분리했다. 웹·설치 앱에서 최종 카카오 요청에 닉네임만 포함되도록 수정했고, 실제 SDK·Auth를 사용하는 두 회귀 테스트가 실패 후 통과했다. 전체 Vitest 171/171, 타입 검사, 웹·Worker 빌드가 통과했다. Chrome의 실제 오류 설명에서도 미설정 항목이 세 개에서 닉네임 하나로 줄었음을 확인했다. 사용자가 닉네임 설정을 저장한 뒤 Chrome에서 KOE205 없이 회원번호·닉네임 제공 동의 화면이 나타났다. 이후 사용자가 직접 동의했고 실제 callback 성공, 주소의 인증 코드 제거, 계정 조건 저장·새로고침·로그아웃 후 재로그인 복원을 확인했다. 같은 카카오 계정이 중복 생성되지 않았고, 이메일 없이 생성된 profile에 현재 기본 조건인 지하철 30분이 저장됨을 확인했다. 토큰·회원번호·개인정보 원문은 검증 출력에 포함하지 않았다.

최신 코드 검증은 Vitest 171/171과 타입·웹/Worker 빌드다. 이전 전체 기능 검증에서는 DB 권한 35/35, 브라우저 시나리오 10/10, 빈 임시 DB 마이그레이션 12개 재실행을 통과했다. 이번 실제 계정 검증은 위 수동 확인에 해당하며, 동일 자동 검증을 재실행한 것으로 표시하지 않는다. 전체 코드 검토의 Important 3건을 재현 후 수정했고 미룬 경미 사항은 없다. 실제 앱 빌드는 Xcode·JDK 부재로 실패했으며 자산 동기화와 Swift 문법 검사만 확인했다.
